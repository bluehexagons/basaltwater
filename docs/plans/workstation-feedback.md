# Workstation feedback implementation

The October 2026 CachyOS/Antistatic feedback is evaluated against existing
Basaltwater interfaces. Shared workflow and evidence conventions apply across
projects; platform-specific execution remains with each platform's commands.
Native validation on other supported platforms is a later acceptance phase.

| Feedback | Existing capability | Change |
| --- | --- | --- |
| Concise capability report | Scoped manifest, CachyOS doctor, explicit GLX doctor | Opt-in workstation manifest with bounded metadata and explicit unknown readiness |
| Workflow entry points | Native development, Blender smoke, project visual recipes | One short workflow route page linking the owning commands |
| Instruction ownership | Repository policy, installed skills, orchestration references | Explicit ownership and precedence; keep delegation out of desktop operation guidance |
| Current-state notes | Revision-checked local project memory | Shared current checkpoint, separate history, completed/obsolete script convention |
| Command results | Private capture helper, visual reports, Blender evidence, task logs | Reuse these interfaces; document the common minimum and add task duration evidence |
| Owned processes | Native development transient units and guarded stop; portal session ownership | Expose task unit process metadata and completion evidence; retain identity guards |
| Handoffs | Existing project/visual qualification guidance | Lightweight implementation, visual review and hardware acceptance templates |

No private Antistatic files are copied into Basaltwater. Repeatable rendering
logic belongs in that project's reviewed harness and `basaltwater-agent.json`;
Basaltwater owns launching, evidence collection and platform operation. Existing
user-session applications are never adopted or stopped by name.

Validation evidence and unfinished work belong in a local current checkpoint,
not a running chronological log in this plan. A command exit or prerequisite
report is not hardware acceptance. Record actual checks, environment and revision
in each handoff; leave unperformed checks explicitly unverified.

The [Debian continuation handoff](workstation-feedback-debian.md) records the
CachyOS second-pass findings, observed checks, platform boundaries and next
validation work for the receiving agent.
