# T3 Code 0.1.12 integration

Reviewed on **2026-11-25 UTC**. GitHub's latest stable release and npm's
`t3@latest` both resolved to **0.1.12**. The tagged commit is
`ca81b7b97a1c4b91e5ac25768d0f6629f37732fd`.
[Upstream release](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12)

## Runtime and access

- The standalone archive layout, launcher protocol **4**, and remote update
  compatibility with protocol **3** carry forward. Database migrations advance
  from **102 to 117**, including tracked project folders, worktree layout
  approvals and workflow journals. Preserve the recovery copy and upstream
  downgrade guard. [Launcher protocol](https://github.com/pingdotgg/t3code/blob/v0.1.12/apps/server/src/cloud/serviceProtocol.ts)
  · [Migrations](https://github.com/pingdotgg/t3code/blob/v0.1.12/apps/server/src/persistence/Migrations.ts)
- The pairing helper's 16-permission grant remains compatible. Initial
  Connect setup still uses the owner-side `relay:configure` grant.
  [Auth contract](https://github.com/pingdotgg/t3code/blob/v0.1.12/packages/contracts/src/auth.ts)
  · [Managed pairing](../../services/device-pairing.md#t3-connect-management)
- Provider recommendations carry forward from [0.1.11](0.1.11.md).
  Check the selected environment's live provider settings and runtime.
  [Provider manifest](https://github.com/pingdotgg/t3code/blob/v0.1.12/apps/server/src/provider/model-manifest.json)

## Features

- **Multi-repository projects** can combine discovered repositories,
  explicitly tracked folders and submodules. Verify actual checkout and
  base per repository. Shared files outside repositories in a plain project
  folder can be changed by any thread using that folder. Basaltwater's
  sparse preflight reports when committed `t3.json` declares a custom
  layout that needs an actual worktree test.
  [Project preflight](../project-manifests.md#t3-code-project-actions-and-worktrees)
- **Workflows (beta)** add durable multi-step runs with saved results,
  triggers and human questions. The starting environment owns the run and
  its journal. Keep existing schedule ownership until the migration has
  been verified. Use Basaltwater jobs for host operations or independent
  lifetime budgets and receipts.
  [Workflow guidance](../../../common/agent_skills/basaltwater-subagents/references/t3-scheduling.md#durable-workflows)
- **Linked threads and connections map (beta)** show routes and grants
  and let clients read threads over an existing link. Interacting requires
  a reachable direct connection and an applicable grant.
  [Linked-environment guidance](../../../common/agent_skills/basaltwater-subagents/references/t3-orchestration.md#linked-environments)
- **MCP sign-in** is available from affected Codex and Claude threads,
  including remote provider instances. [Provider sign-in](../t3-providers.md#provider-sign-in)
- **Apple Speech** is a local dictation option in the macOS 26+ desktop app.
  **Large file previews** can open full files in the client. Basaltwater
  manages host setup and leaves both client features to upstream.
  [Voice input](https://github.com/pingdotgg/t3code/blob/v0.1.12/docs/user/voice-input.md)
  · [Release notes](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12)

## Verification

GitHub-digest-verified Linux x64 archives passed disposable fresh startup and
a 0.1.11-to-0.1.12 upgrade. A fresh npm cache resolved the 0.1.12 CLI and
displayed its service-install help. Both server paths passed HTTP startup
through Basaltwater's output filter, embedded PTY and dotenv probes, one-use
pairing with all 16 permissions, bootstrap-session revocation, the read-only
idle query, signal forwarding and SQLite integrity. The 0.1.12 preflight
accepted the migration-102 database with protocols 3 and 4. The 0.1.11
preflight refused the upgraded migration-117 database.

On the fresh server, the project CLI discovered two nested repositories and
registered a third outside folder. A synthetic workflow reused the same run
on duplicate starts, retained its open question across a server restart, and
completed after an answer without rerunning the finished step.

See the [qualification matrix](../t3-qualification.md#stable-feature-qualification)
for managed systemd, native clients, provider, and Connect cases.
