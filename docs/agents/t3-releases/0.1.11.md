# T3 Code 0.1.11 integration

Reviewed on **2026-11-20 UTC**. GitHub's latest stable release and npm's
`t3@latest` both resolved to **0.1.11**. The tagged commit is
`59651c1761f6c63e9b6056839067066968e6a406`.
[Upstream release](https://github.com/pingdotgg/t3code/releases/tag/v0.1.11)

## Runtime and access

- Launcher protocol **4**, compatibility with protocol **3** launchers,
  version selection and the standalone Linux archive layout carry forward.
  Native Windows Task Scheduler files now use UTF-16LE with a BOM.
  Basaltwater's Windows profile uses the packaged desktop. Database migrations
  advance from **96 to 102**, including issue tracker bindings and projection
  indexes. The local updater checks database compatibility before switching
  builds. [Launcher protocol](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/server/src/cloud/serviceProtocol.ts)
  · [Migrations](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/server/src/persistence/Migrations.ts)
  · [Local updater](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/server/src/cli/update.ts)
- The pairing helper's 16-permission grant matches upstream's standard client
  grant. Initial Connect linking and relay configuration now require
  `relay:configure`. The managed Debian workflow uses the native host command
  for initial linking. Direct-pairing sessions and peer links can renew with
  device-bound keys when both ends support renewal.
  [Pairing operations](../../services/device-pairing.md#t3-connect-management)
  · [Upstream permission contract](https://github.com/pingdotgg/t3code/blob/v0.1.11/packages/contracts/src/auth.ts)
  · [Remote access](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/user/remote-access.md)
- Codex, Claude Code, Grok, OpenCode 2 and Pi recommendations carry forward
  from [0.1.10](0.1.10.md). Antigravity now recommends **1.5.12 to below 2**
  and marks releases below **1.5.0** broken for this T3 version. Use the live
  provider catalog for options and readiness.
  [Provider compatibility manifest](https://github.com/pingdotgg/t3code/blob/v0.1.11/apps/server/src/provider/model-manifest.json)

## Workflow changes

- Compatible desktop clients can render remote loopback tabs locally or
  forward a port to the client. Mobile can open the remote tab on the device.
  The host's Preview tunnel setting defaults on, and managed policy can disable
  it. Server-hosted tabs continue streaming. Use the existing gateway for a
  separately reachable HTTPS URL. [Preview routing](../browser-t3-preview.md#collaborative-preview-and-private-networks)
- Native issue tracking covers GitHub, GitLab, Forgejo, Azure DevOps and
  connected Linear projects. T3 owns tracker access and thread links. Native
  PR and CI tools can change remote state with the appropriate permissions.
  Follow the active session's authorization and tool schemas.
  [Issues and stacks](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/user/source-control.md#issues)
- `t3_thread_launch` accepts a request key that lets the original provider
  session retry a lost response. New worktrees can use a sparse checkout
  configured on the selected branch. [Launch contract](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/orchestration-v2/orchestrator-mcp-server.md#t3_thread_launch)
  · [Project settings](https://github.com/pingdotgg/t3code/blob/v0.1.11/docs/user/project-settings.md#defaults-and-inheritance)

## Verification

GitHub-digest-verified Linux x64 archives passed a fresh 0.1.11 startup and a
0.1.10-to-0.1.11 upgrade in disposable homes. The published npm launcher also
reported `t3 v0.1.11` from a fresh cache. Both 0.1.11 server runs passed HTTP
200 startup, filtered startup output, signal forwarding, embedded native PTY
and dotenv probes, one-use pairing redemption with all 16 permissions,
bootstrap-session revocation, and Basaltwater's read-only idle query. The paired
session reported that initial Connect linking was unavailable. SQLite integrity
passed after shutdown. Upgrade preflight accepted the migration-96 database
under launcher protocols 3 and 4. The 0.1.10 preflight refused the upgraded
migration-102 database.

These trials ran a standalone server on loopback with disposable data.
Live systemd lifecycle, authenticated provider turns, native Windows/CachyOS
clients, renewal, preview tunneling and tracker workflows require separate
[live qualification](../t3-qualification.md#stable-feature-qualification).
